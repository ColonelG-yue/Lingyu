# 媒体独立页与快捷操作去重设计

## 目标

解决首页同时显示媒体播放器和日历时的宽度冲突，并移除“快捷控制”中与顶部独立模块重复的跳转卡片。

本轮同时交付：

1. 独立媒体标签页。
2. 重新定义后的快捷操作页。

## 当前问题

- `NotchHomeView` 在同一个横向布局中同时放置完整媒体播放器、日历和可选镜子。
- 媒体封面与控制区缺少上限宽度，日历会被压缩成窄条。
- 快捷控制中的剪贴板、Shelf、媒体、系统、Codex、终端都已有独立入口，页面只承担重复跳转。

## 顶部导航

- 保留首页入口。
- 在首页与 APP 之间增加媒体入口，使用 `play.circle.fill` 风格图标。
- 保留快捷操作入口，但不再显示模块跳转卡片。
- 媒体开始播放时不自动切换标签，避免打断日历或其他页面。
- 灵动岛重新展开时继续恢复上次使用的标签。

## 首页

- 首页不再渲染完整 `MusicPlayerView`。
- 首页继续承载日历；后续天气与日历紧凑卡片接入此位置。
- 当前音乐在灵动岛收起状态下仍可作为紧凑媒体状态显示，不影响展开后的标签选择。
- 镜子继续按现有开关显示，但不得与日历、媒体共享三等分宽度。

## 独立媒体页

### 有播放内容

- 媒体页独占可用内容宽度。
- 左侧封面使用明确的最小和最大尺寸，不随窗口无限放大。
- 中间区域显示歌曲标题、艺人、播放进度和播放控制。
- 右侧区域用于歌词、媒体输出或后续播放队列；没有可用内容时由中间区域扩展占满。
- 页面整体必须适配当前约 `792 × 363` 的普通展开尺寸以及用户调整后的尺寸。

### 无播放内容

- 显示“当前没有正在播放的媒体”。
- 提供打开最近媒体应用的按钮；无法识别应用时只显示空状态，不报错。

### 交互

- 点击顶部媒体图标进入媒体页。
- 点击收起态的封面或媒体状态可进入媒体页并展开灵动岛。
- 媒体页不会与日历同时渲染。

## 快捷操作页

### 删除的重复入口

- 剪贴板页面跳转。
- Shelf 页面跳转。
- 媒体页面跳转。
- 系统监控页面跳转。
- Codex 页面跳转。
- 终端页面跳转。

### 默认直接操作

- 启动 25 分钟专注计时。
- 新建临时笔记。
- 打开下载文件夹。
- 清空剪贴板历史，执行前需要二次确认。
- 弹出独立系统监控窗口。
- 运行用户固定的 macOS 快捷指令；未配置时显示设置提示。

### 配置与排序

- 快捷操作使用稳定的动作标识，而不是直接保存闭包或视图状态。
- 用户可在简洁设置中心选择显示动作并拖动排序。
- 第一版提供六个位置；不足六个时不显示空占位卡。
- 不可用动作显示原因，不静默失败。

## 数据与状态

- 标签选择继续使用现有标签状态和上次页面持久化机制。
- 媒体数据继续来自 `MusicManager`，不新增第二套播放器状态。
- 计时器、笔记、剪贴板、系统监控分别复用现有 Manager。
- 快捷操作配置使用 `Defaults` 持久化动作 ID 顺序。

## 错误处理

- 无媒体会话：显示空状态。
- 媒体封面缺失：显示来源应用图标或系统媒体图标。
- 快捷指令不存在：动作保持可见并提示重新选择。
- 下载文件夹无权限：显示权限说明和设置入口。
- 系统监控未启用：执行快捷操作时先启用必要监控，再弹出窗口。
- 清空剪贴板历史：必须二次确认，防止误操作。

## 验收标准

1. 播放媒体时，首页日历宽度不再被媒体播放器压缩。
2. 媒体页在普通展开尺寸下没有截断、重叠或异常放大的封面。
3. 从其他标签切回媒体页时播放状态和进度连续。
4. 开始播放不会自动抢占当前标签。
5. 快捷操作页不再出现六个模块跳转卡片。
6. 六个默认动作中，除需要权限或用户配置的动作外，都能直接执行。
7. 不可用动作有明确中文提示。
8. 现有 APP、Shelf、Codex、计时器、系统和终端页面仍可正常进入。

## 测试

- 编译 Debug 配置并运行 Atoll Dev。
- 分别测试无媒体、播放、暂停、切歌和封面缺失状态。
- 在日历有事件和无事件时检查首页布局。
- 调整展开尺寸后检查媒体页响应式布局。
- 逐个执行快捷动作，验证成功状态和错误提示。
- 验证重新启动后恢复上次标签以及快捷动作顺序。

## 本轮不包含

- 播放队列编辑。
- 新媒体数据源或第三方音乐服务集成。
- 天气与日历紧凑卡片的完整实现。
- Nook X 风格设置中心和统一提醒引擎的实现。
