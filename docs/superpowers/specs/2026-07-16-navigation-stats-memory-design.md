# Atoll 导航、系统监控与内存优化设计

## 目标

本轮只处理已确认的交互闭环，并避免继续增加重复入口：

- 设置页右上角在红色退出按钮左侧增加黄色最小化按钮。
- 双指横向切页降低误触，切页动画放慢并增加稳定感。
- 终端保留纵向滚动，同时允许明确的横向手势切换页面。
- 系统监控成为始终可见的灵动岛顶部页；未启用时在页内一键开启。
- 剪贴板历史使用独立顶部页，不再与笔记或专注计时器共用入口条件。
- 删除快捷控制中的系统监控卡片和系统监控独立窗口。
- 对常驻内存做低风险优化，不牺牲剪贴板图片拖放、终端保持和页面记忆。

## 交互设计

### 设置窗口

在现有红色退出按钮左侧放置一个小号黄色减号按钮。按钮调用设置窗口自身的 `miniaturize`，只缩小设置窗口，不关闭 Atoll 或灵动岛。

### 横向切页

滚动事件先经过方向意图判断。只有横向位移明显大于纵向位移时才锁定为切页，避免斜向滚动误触。普通双指手势需要达到更高的距离或速度门槛；速度触发还必须有最低位移，避免轻碰立刻切页。一次手势最多切换一页。

切页使用约 0.30 秒的低回弹弹簧动画。拖动采样过程不附加动画，只有确认切页时执行动画。

终端区域继续接收纵向滚动；当统一手势监听器确认是横向意图时，允许切换顶部页。输入框或终端焦点不再完全屏蔽横向切页。

### 系统监控

顶部导航始终显示“系统”页。关闭统计功能时，页面展示说明和“一键启用”按钮；开启后显示已有 CPU、内存、GPU、网络和磁盘卡片，并保留指标选择菜单。

快捷控制不再提供系统监控卡片。删除独立系统监控窗口及其弹出按钮，确保系统监控只有一个主要入口。

## 内存策略

先以活动监视数据作为基线。当前常驻内存约 75 MB，不属于异常偏高，但仍优化以下热点：

- APP Finder 的应用图标使用有数量上限的 `NSCache`，避免 SwiftUI 重绘时反复解码同一图标。
- 应用目录扫描结果在进程内复用，避免每次进入 APP 页都重新遍历固定目录。
- 保留统计历史长度上限和后台停采样策略，不让系统监控因为“始终有入口”而始终采样。
- 不把剪贴板原始图片永久复制进额外内存缓存；拖放继续按需读取现有持久化数据。

## 验收标准

- 设置页黄色按钮能把设置窗口缩小到 Dock，红色按钮仍退出应用。
- 双指轻扫不再误触；明确横扫只切一页，动画不突兀。
- 终端内可上下滚动，也可明确左右滑动切页。
- 顶部有系统页；关闭状态可一键启用；快捷控制没有系统卡片；不存在独立窗口按钮。
- APP 页面多次进入不重复扫描/解码全部应用。
- Debug 构建通过，关键 UI 测试通过，启动后内存没有明显回归。
